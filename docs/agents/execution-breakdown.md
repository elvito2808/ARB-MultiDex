## ترتیب تحویل و پذیرش

- بخش ۱ مبنای هویت مشترک است. بخش ۴ رابط داده را با ۲ و ۳ هماهنگ می‌کند. طراحی معیارهای بخش ۹ می‌تواند از آغاز پیش برود. آزمون سرتاسری به قراردادهای مصرف‌شده وابسته است.
- بخش ۵ برای تثبیت ورودی Quote منتظر بازبینی مستقل S2 و پذیرش SIM-01 توسط Agent 0 است. [SIM-01، بازنگری ۱](https://github.com/elvito2808/ARB-MultiDex/blob/c63f0c57740013d297c2af819e2829c8ea4f1e87/docs/design/quote-contract.md) روی `sim-01-quote-contract` آماده بازبینی است. شواهد تهیه‌کننده ثبت شده‌اند. پذیرش مستلزم گزارش مستقل روی همین SHA و تطبیق با مقصد است.
- بخش‌های ۶ و ۷ رابط پذیرش، توقف و بازیابی را مشترک تعریف می‌کنند. بخش ۸ قرارداد رویداد را با تولیدکنندگان هماهنگ می‌کند. پذیرش طرح عملیات ۱۰ به شواهد سلامت، بازیابی و آزمون بخش‌های وابسته نیاز دارد.
- Agent 0 برای هر بسته شاخه، SHA مبنا، مسیرهای مجاز، معیار پذیرش و بازبین مستقل را طبق [تحویل دستی](handoff.md) ثبت می‌کند. تخصیص پیشنهادی ۱ و ۱۰ از مرز نقش‌های موجود پیروی می‌کند. بازبینی خروجی S5 طبق قاعده موجود با Agent 0 است.
- موارد D-01 تا D-05 در [رجیستر تصمیم‌ها](decisions.md) باز هستند. نام‌هایی مانند KuCoin و مصادیق DEX، شبکه، توکن و قرارداد در منابع، سناریوی مرجع‌اند. انتخاب محصول و ترتیب اجرا با مالک است. دامنه مصوب جاری مستندات، طراحی غیرعملیاتی و شبیه‌سازی با داده ساختگی است.
