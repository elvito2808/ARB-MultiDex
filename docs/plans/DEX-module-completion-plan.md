# برنامه تکمیل ماژول DEX

**مبنای نیازمندی:** `DEX_Module_Requirements_v1.0.md`  
**بازار مرجع انتخاب‌شده:** Hedera Mainnet / SaucerSwap V1 / WHBAR-USDC  
**زبان پیاده‌سازی:** Python (تصمیم قطعی مالک در 2026-11-24)  
**وضعیت فعلی:** تحقیق بازار پذیرفته شده؛ پیاده‌سازی ماژول آغاز نشده است. هدف زمانی فعلی، MVP قابل اجرا در حالت SIMULATION/DRY-RUN است؛ LIVE خارج از دامنه است.

## 1. مرز قطعی کار

ماژول DEX باید DEX، شبکه، جفت و استخر انتخاب‌شده را بشناسد، اطلاعات قرارداد را از طریق Connections مدیریت‌شده بخواند، برای حجم پایه مشخص‌شده دو Quote مستقل BUY و SELL محاسبه کند، هزینه‌های مرتبط و اعتبار زمانی را لحاظ کند و خروجی معتبر را به مصرف‌کننده تحویل دهد.

خارج از دامنه DEX: مقایسه با KuCoin، تشخیص فرصت، تصمیم معامله، مدیریت ریسک، رزرو موجودی، اجرای سفارش یا تراکنش و انتخاب خودکار استخر.

هر جفت فقط استخر انتخاب‌شده توسط مالک را استفاده می‌کند. جفت باید یک دارایی غیر استیبل‌کوین و یک استیبل‌کوین داشته باشد. حجم پایه برای هر جفت مستقل و قابل تنظیم است. معماری باید چند DEX و نسخه پروتکل را پشتیبانی کند و حداکثر سه مسیر شبکه‌ای مستقل را بدون اشتراک وضعیت کهنه مدیریت کند.

## 3. وابستگی‌های تصمیم‌گیری پیش از پیاده‌سازی

### D-02 — زبان و Runtime
زبان Python با تصمیم صریح مالک بسته شده است. مقایسه مجدد زبان یا توقف کار برای انتخاب زبان مجاز نیست. Runtime و وابستگی‌ها باید با انتخاب ساده و قابل نگهداری در جریان پیاده‌سازی تعیین شوند؛ از معماری پیچیده و ابزارهای غیرضروری اجتناب شود.

### D-03 — هزینه‌ها و اعتبار Quote
- **مالک تحلیل:** S2
- **تأمین‌کننده شواهد DEX:** S1
- **بازبین:** S5
- **موارد لازم:** هزینه Swap فقط یک بار؛ هزینه Gas و تبدیل HBAR به USDC؛ هزینه‌های احتمالی Router/Protocol؛ تفکیک هزینه Embedded و Separate؛ روش گردکردن BUY و تطبیق با Router؛ زمان Snapshot و Reserve Update؛ حداکثر عمر Quote و زمان اعتبارسنجی مجدد.
- **خروجی:** قرارداد نهایی BUY total و SELL net، روش هزینه‌ها، فیلدهای Quote و خطاهای رد Quote.
- **معیار پایان:** هیچ هزینه‌ای دوباره کسر نشود و هیچ Quote ناقص به S2 منتشر نشود.

### DEX-to-Quote mapping
- **مسئول:** S2 با S1
- **موضوع:** تطبیق فیلدهای موردنیاز DEX Module §8 (DEX، Network، Pair، Pool، BUY/SELL، Base Volume، Stable Amount، Price، Costs، Timestamp و Validity) با قرارداد عمومی Quote در SIM-01.
- **معیار پایان:** هر فیلد دارای مقصد روشن باشد؛ در صورت نیاز به تغییر قرارداد، پیشنهاد تغییر جداگانه ثبت شود. هیچ فیلدی بی‌صدا حذف یا با Symbol جایگزین نشود.

## 4. پیاده‌سازی بازار مرجع — S1

**مالک:** S1  
**بازبین طراحی:** S2  
**بازبین امنیت و آزمون:** S5  
**هماهنگ‌کننده:** Agent 0

### 4.1. شناسنامه و پیکربندی بازار
- DEX ID و نسخه SaucerSwap V1
- Network ID و Chain ID برابر 295
- Pair: WHBAR/USDC
- Pool address انتخاب‌شده توسط مالک
- Token addresses و decimals تأییدشده
- Pool fee برابر 30 bps، بدون اعمال دوباره
- حجم پایه WHBAR به‌صورت تنظیم مستقل؛ مقدار هنوز باید در تنظیمات مشخص شود
- کنترل تطبیق Token0/Token1 و عدم اتکا به ترتیب نمادها

### 4.2. ABI و خواندن قرارداد
- Pair ABI برای `token0()`, `token1()`, `getReserves()`
- Token ABI برای getterهای لازم مانند `decimals()` و `symbol()`
- Factory ABI برای بررسی اختیاری منشأ Pair و `getPair()`
- Router ABI فقط اگر برای cross-check محاسبه لازم باشد؛ نه برای ارسال تراکنش
- هر ABI باید نام، نسخه، منبع و قراردادهای سازگار مشخص داشته باشد.
- خواندن قرارداد در DEX انجام شود؛ Connections فقط رابط RPC مدیریت‌شده را فراهم کند.
- همه خواندن‌های یک Quote باید به یک Snapshot/Block مشخص متصل باشند.

### 4.3. Price Calculator
- BUY: محاسبه مقدار USDC لازم برای دریافت مقدار دقیق WHBAR تعیین‌شده.
- SELL: محاسبه مقدار USDC حاصل از فروش همان مقدار WHBAR.
- استفاده از integer arithmetic و واحدهای atomic؛ بدون float برای محاسبه مالی.
- اعمال کارمزد Pool دقیقاً یک بار.
- لحاظ‌کردن اثر حجم معامله بر قیمت.
- لحاظ‌کردن Gas و تبدیل آن به USDC طبق تصمیم D-03.
- رد reserve صفر، مقدار نامعتبر، BUY برابر/بزرگ‌تر از reserve پایه و SELL با خروجی صفر.
- رفتار rounding در مرز تقسیم دقیق باید با Router منتخب تعیین و تست شود.

### 4.4. اعتبار و خروجی
- ثبت زمان بلاک/مشاهده، زمان آخرین تغییر Reserve و زمان دریافت محلی به‌صورت مجزا.
- کنترل شبکه، بلاک، Pair، Tokenها، اعشار و Snapshot سازگار.
- رد داده ناقص، قدیمی، تکراری، عقب‌گرد بلاک یا Snapshot ناسازگار.
- خروجی شامل شناسه DEX، شبکه، Pair، Pool، جهت، حجم پایه، مبلغ USDC، قیمت، هزینه‌های اعمال‌شده، زمان و وضعیت اعتبار باشد.
- خروجی با Quote Contract پذیرفته‌شده SIM-01 منطبق شود.

## 5. Connections — S1 با همکاری S4/Agent 0

- RPC اصلی و جایگزین برای Hedera، پس از تصمیم/تأیید endpoint.
- Chain ID واقعی برابر 295 در اتصال اولیه، reconnect و failover.
- سلامت RPC، timeout، HTTP 429/5xx، RPC error، lag و داده تاریخی.
- Fallback فقط پس از اعتبارسنجی شبکه و تازگی؛ Snapshot ناقص بین دو endpoint ترکیب نشود.
- DEX نباید URL خام را مدیریت کند یا خودش سیاست اتصال موازی بسازد.
- هر یک از حداکثر سه Worker شبکه‌ای باید Snapshot، Cache، زمان و خطاهای مستقل داشته باشد.

## 6. آزمون و امنیت — S5

### آزمون‌های لازم
- هویت شبکه، Pair، Factory و Tokenها؛ Token order و decimals.
- ABI decoding، داده کوتاه/اضافی/خراب، revert و پاسخ RPC نامعتبر.
- BUY و SELL برای حجم یکسان با integer arithmetic.
- کارمزد 30 bps دقیقاً یک بار و اثر قیمت.
- rounding عادی و exact division.
- reserve صفر، BUY در حد reserve یا بیشتر، SELL با خروجی صفر، اعداد بزرگ و حجم غیرقابل نمایش.
- Snapshot در بلاک یکسان، بلاک قدیمی/تکراری/عقب‌رفته و Reserve Update قدیمی.
- timeout، قطع RPC، 429، 5xx، خطای RPC داخل HTTP 200، fallback اشتباه و بازیابی.
- اثبات عدم امضا، عدم ارسال تراکنش، عدم Approval و عدم انتقال دارایی.
- سه مسیر شبکه مستقل، عدم نشت Cache و عدم انتشار داده کهنه از یک Worker به دیگری.

### معیار امنیتی قطعی
این مرحله فقط Read-only است. هیچ کلید خصوصی، Wallet، امضا، تراکنش، Approval، انتقال، wrap/unwrap یا LIVE execution ایجاد نشود.

## 8. معیار تکمیل ماژول DEX

ماژول فقط وقتی تکمیل‌شده اعلام می‌شود که:
1. زبان Python مطابق تصمیم مالک استفاده شده باشد و D-03 به‌اندازه لازم برای Quote صحیح تعیین تکلیف شده باشد.
2. Adapter واقعی Read-only برای بازار انتخاب‌شده در مخزن وجود داشته باشد.
3. ABIها و تنظیمات بازار نسخه‌بندی و قابل اعتبارسنجی باشند.
4. BUY و SELL برای حجم یکسان، با هزینه‌ها و rounding تعیین‌شده محاسبه شوند.
5. خروجی با قرارداد Quote مصرف‌کننده سازگار باشد.
6. Quote قدیمی/نامعتبر/ناسازگار هرگز منتشر نشود.
7. خطا و بازیابی RPC و Snapshot آزموده شوند.
8. تست‌های امنیتی ثابت کنند هیچ عملیات نوشتنی/مالی انجام نمی‌شود.
9. بازبینی مستقل S2 و S5 انجام و یافته‌های مسدودکننده بسته شده باشند.
10. Agent 0 نتیجه را در مخزن ثبت و به‌عنوان تکمیل‌شده بپذیرد.

**مواردی که خارج از معیار این مرحله‌اند:** اتصال KuCoin، تشخیص فرصت، اجرای معامله، فعال‌سازی LIVE و انتخاب خودکار استخر.
